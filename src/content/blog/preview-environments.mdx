## Installing the CLI

Pick your package manager. Every snippet in the same group on this page switches with it:

<CodeTabs group="pkg">

```sh title="npm"
npm install -g shipit-cli
```

```sh title="pnpm"
pnpm add -g shipit-cli
```

```sh title="yarn"
yarn global add shipit-cli
```

</CodeTabs>

Then configure which services to watch:

<CodeTabs>

```yaml title="shipit.yaml"
services:
  - name: api
    path: services/api
  - name: web
    path: apps/web
preview:
  ttl: 7d
  seed: snapshots/small.sql
```

```json title="shipit.json"
{
  "services": [
    { "name": "api", "path": "services/api" },
    { "name": "web", "path": "apps/web" }
  ],
  "preview": { "ttl": "7d", "seed": "snapshots/small.sql" }
}
```

</CodeTabs>

## Building only what changed

The key to speed is not rebuilding the world. We compute which services a diff touches:

```ts
export async function changedServices(base: string, head: string): Promise<string[]> {
  const files = await git.diff(['--name-only', `${base}...${head}`]);
  return services.filter((s) => files.some((f) => f.startsWith(s.path)));
}
```

### Caching layers

Docker layer caching does most of the heavy lifting. Order your `Dockerfile` from least to most
frequently changing.

Kick off a preview manually:

<CodeTabs group="pkg">

```sh title="npm"
npx shipit deploy --env preview
```

```sh title="pnpm"
pnpm dlx shipit deploy --env preview
```

```sh title="yarn"
yarn dlx shipit deploy --env preview
```

</CodeTabs>

> [!IMPORTANT]
> Preview environments share the cluster with production workloads. Give them their own node pool and
> resource quotas.

## Seeding data

An empty database makes a useless preview. We restore a small, anonymised snapshot on namespace creation.

> [!CAUTION]
> Never seed previews from a raw production dump. Anonymise **first**, then snapshot.

## Cleaning up

Namespaces are deleted when the PR closes, plus a nightly sweep for anything older than seven days.

> The best infrastructure is the kind reviewers never have to think about.
